# Collect 品牌与视觉识别研究

> 后续状态：用户已选定名称 **Dearshelf** 与南瓜猫窝睡猫的第二版插画，并授权应用到 Android 手机。本文保留为研究阶段记录；最新选择与落地范围见 [brand_selection.md](brand_selection.md)。

研究日期：2026-10-01。阶段：Research → Strategy → Concepts。

本轮约束更新：品牌名只考虑英文；默认图标采用清新、明亮的配色；核心感受按用户原话确定为“为我的喜欢留位置，让我看到它们就很开心”。据此优先推荐 **B · 为喜欢留位置**，同时保留“被认真看见”和“日常里的小世界”两条表达路线供选择。本版已撤下上一版中文名称和暗色提案，仍未决定最终品牌方向、名称或生成正式资源。

本次研究以“私人数字收藏空间”为定位，产出品牌方向与名称初筛。Collect 仍是项目现名。本文不确定最终名称，不提供最终 Logo，不涉及应用代码、现有 UI、包名、平台显示名称或图标资源的修改。

## 1. 研究范围与证据方法

研究了 14 个案例：Things、Day One、Letterboxd、Pinterest、Raindrop.io、mymind、Are.na、Sofa、Craft、Notion、Arc / Arc Search、Cosmos、Flighty、Bears Gratitude。

样本覆盖私人记录、内容收藏、个人空间、独立产品、强识别主流品牌，以及 Apple Design Award 案例。Flighty 是 2023 年 Interaction 获奖产品；Bears Gratitude 是 2024 年 Delight and Fun 获奖产品。奖项信息以 [Apple 2023 年名单](https://developer.apple.com/design/awards/2023/)及 [2024 年名单](https://developer.apple.com/design/awards/2024/)为准，不将“年度 App”“奖项入围”“设计奖获奖”混为一谈。

证据优先级：官方品牌资产与开发者网站 → 开发者发布的 App Store 图标、截图和介绍 → Apple / Android 官方规范。已通过 Apple 公开接口读取上述产品的图标与截图，并进行视觉对照；这些图像只用于临时研究，没有作为 Collect 的资源加入仓库。

下文区分三种信息：

- **事实**：官方明确陈述的产品定位、品牌元素、规范与奖项。
- **视觉观察**：本次官方图标、产品截图、品牌页面呈现的形状、颜色和排版。商店截图可能早于最新版本，不能代替完整真机体验。
- **设计推断**：“为什么有效”及对 Collect 的启发。除明确标注外，不代表原设计师的创作自述，也不代表已完成用户验证。

配色描述是视觉观察，不冒充竞品的精确品牌色值。字标分析讨论文字与符号的分工、大小写和排版气质，不猜测专用字体名称。Arc 的官网目前将 Dia 放在重要位置；本研究保留 Arc 的品牌方法案例，不把它当作活跃开发状态的产品推荐。[Arc 官网](https://arc.net/)

## 2. 竞品与优秀品牌案例

### 2.1 Things：普通词语与核心动作形成稳定联系

- **命名**：Things 是常用复数词，语义开放。推断：不把产品绑定到某一种任务类别，名字易读，但新品牌直接使用同类常用词会有搜索成本。
- **Icon / Logo**：蓝色容器轮廓与勾选符号，核心动作非常直接。官方介绍 OS 26 更新时明确保留熟悉的蓝色盒形，只调整表现方式。[官方更新说明](https://culturedcode.com/things/blog/)
- **字标 / 配色**：短英文名称与独立图标分工；蓝色建立识别，正文界面保持清楚、克制。
- **UI 延续**：勾选、列表、Inbox 等语义与图标相互支撑，品牌通过任务完成体验延续，不要求所有控件都长成盒子。
- **为什么有效 / Collect 启发**：先稳定“识别骨架”，再适应系统外观。Collect 应找到自己的核心感受；勾选会强调完成任务，不宜直接移植。

来源：[产品官网](https://culturedcode.com/things/)、[官方图标与截图](https://apps.apple.com/us/app/things-3/id904237743)。

### 2.2 Day One：名称表达开始，符号表达记录

- **命名**：Day One 是易懂的时间短语，能联想到个人生活的起点；这是语义分析，而非命名来源的考证。
- **Icon / Logo**：蓝底上保留白色书签形负空间，轮廓比一本完整日记本更简洁。
- **字标 / 配色**：名称可独立阅读，蓝白组合让记录显得清爽；不依赖图标里的小字。
- **UI 延续**：日期、照片、日记与回顾共同组织个人经历，品牌感来自持续记录。[官方产品介绍](https://dayoneapp.com/)
- **为什么有效 / Collect 启发**：抽取一个“记录”的符号，比画所有日记功能更容易缩小。可学习私人感和回看体验；不要把 Collect 变成以长篇写作为中心的日记产品。Day One 的隐私技术承诺也不能直接移作 Collect 的承诺。

图像校对：[App Store](https://apps.apple.com/us/app/day-one-daily-journal-diary/id1044867788)。

### 2.3 Letterboxd：简单符号可以承载高度具体的兴趣身份

- **命名**：Letterboxd 与电影画幅词汇形成联想，末尾拼写增加辨识；不是“电影管理器”的功能式名称。
- **Icon / Logo**：橙、绿、蓝三个重叠圆点。官方称其为 dots device，并提供彩色、单色与不同组合版式。[官方品牌页](https://letterboxd.com/about/brand/)
- **字标 / 配色**：圆点与清楚的完整字标并用；深色背景给电影海报让位，三色用于建立识别。
- **UI 延续**：海报、评分与观影记录构成体验，图标并不逐项描绘这些功能。
- **为什么有效 / Collect 启发**：品牌符号负责被认出，内容负责讲故事。不能直接借用三圆点、三色次序或其电影社区身份。

图像校对：[App Store](https://apps.apple.com/us/app/letterboxd/id1054271011)。

### 2.4 Pinterest：字母成立的前提是独特处理与长期一致

- **命名**：Pin 与 interest 的组合可以同时联想到保存与兴趣；名字、行为和视觉形成一套语言。
- **Icon / Logo**：红色圆形徽记里的白色、手写感 P。它不是未经处理的系统字体首字母。官方也提供受限色彩场景的黑白使用方式。[官方品牌规范](https://business.pinterest.com/brand-guidelines/)
- **字标 / 配色**：徽记承担小尺寸识别，完整名称承担阅读；红色是强识别信号，内容本身保持多样颜色。
- **UI 延续**：Pin、保存动作和图片流互相呼应，不靠在每张图片上加 Logo。
- **为什么有效 / Collect 启发**：字母可以成功，但“画一个 C”没有自动获得相同的品牌价值。应先有产品概念和独特轮廓，再判断是否需要字母。

图像校对：[App Store](https://apps.apple.com/us/app/pinterest/id429047995)。

### 2.5 Raindrop.io：名称隐喻与图形不必逐字对应

- **命名**：Raindrop 是自然物隐喻，.io 提供互联网产品语境；代价是与天气相关结果、同名产品混杂。
- **Icon / Logo**：本次商店图标是青蓝到紫蓝的重叠云形，不应凭名称把它描述成单一水滴。
- **字标 / 配色**：完整名称与云形分开使用，蓝色系进入操作界面；多色集中在标识而非每个信息块。
- **UI 延续**：集合、标签及多种浏览视图以内容整理为中心。[官方产品页](https://raindrop.io/)
- **为什么有效 / Collect 启发**：稳定的云形和轻快色彩可以比功能清单更亲近。但 .io 与云隐喻会强调网络工具；Collect 更需要实物和个人归属感。

图像校对：[App Store](https://apps.apple.com/us/app/raindrop-io/id1021913807)。

### 2.6 mymind：拥有者视角与感性视觉共同表达私人空间

- **命名**：my + mind 是自然短语，直接把主语交还用户；不是“内容数据库”的名称。
- **Icon / Logo**：本次图标是橙色、柔软的抽象雕塑形象，具有材质感，不是脑图或文件夹。
- **字标 / 配色**：小写名称与柔和、感性的宣传排版共同降低工具感；橙色形象与中性界面形成分工。
- **UI 延续**：官方强调私人保存、平静浏览及个人灵感，截图中的保存反馈也延续这种语气。[官网与品牌主张](https://mymind.com/)
- **为什么有效 / Collect 启发**：可以用情绪母题表达“这是我的地方”，不必画真实柜子。不过复杂材质、渐变和 AI 整理能力都不是 Collect 本阶段要照搬的内容。

图像校对：[App Store](https://apps.apple.com/us/app/mymind-extend-your-mind/id1520332347)。

### 2.7 Are.na：关系结构本身就是品牌符号

- **命名**：Are.na 的断点使常见词获得视觉节奏，也增加输入和口述成本；标点辨识不等于搜索独占。
- **Icon / Logo**：黑色双星状节点，中间以连接结构相连；不是常见的四宫格。
- **字标 / 配色**：短字标保留断点，黑白系统让混合内容成为主体。
- **UI 延续**：blocks 与 channels 组织内容关系，截图中的连接操作与核心母题一致。它也包含协作和公开空间，不能整体等同私人收藏柜。[官方介绍](https://www.are.na/about)
- **为什么有效 / Collect 启发**：符号来自内容组织方式，有延续性。Collect 可以借鉴“从关系中提炼图形”的方法，但不应为了一个连接符号新增社交、知识网络或复杂关系功能。

图像校对：[App Store](https://apps.apple.com/us/app/are-na/id1299153149)。

### 2.8 Sofa：一个日常物件可以表达使用心情

- **命名**：Sofa 指向休闲场景，用户先感受到放松，再理解功能。
- **Icon / Logo**：当前默认图标是蓝色背景上的白色、圆润座椅；官方另有大量替代图标，不能把某个替代版本视为唯一标识。
- **字标 / 配色**：短名称容易独立使用；蓝色图标与暖色、柔和内容界面并存，统一来自亲近的形状和语气。
- **UI 延续**：休闲内容的列表、封面和分组服务“享受自己的时间”。[官方产品介绍](https://www.sofahq.com/)
- **为什么有效 / Collect 启发**：具体物件不是一定俗套，关键是它是否代表产品体验。Collect 的“柜子”只有在安放与陈列概念成立时才有意义；不必增加替代图标和主题功能。

图像校对：[App Store](https://apps.apple.com/us/app/sofa-downtime-organizer/id1276554886)。

### 2.9 Craft：名字、模块与使用质感共同表达认真制作

- **命名**：Craft 是真实词，联想到制作与品质；常用词的搜索辨识需要产品积累支撑。
- **Icon / Logo**：四个圆润扇形 / 片状单元，粉、蓝、深蓝构成组合，不能简单读成字母 C。
- **字标 / 配色**：简短字标与彩色模块分工；产品内容与封面可多样，标识保持稳定。
- **UI 延续**：文档、页面和卡片的组合与模块语言呼应。创始人明确讨论工具的使用感受与输出质量。[创始人介绍](https://www.craft.do/about)、[官方媒体页](https://www.craft.do/media)
- **为什么有效 / Collect 启发**：品牌不仅是一枚图标，还包括用户愿意反复打开的质感。可以保留当前 UI 的细致与圆润，不借用四片构图。

图像校对：[App Store](https://apps.apple.com/us/app/craft-notes-documents-ai/id1487937127)。

### 2.10 Notion：字母需要具备自己的图形性格

- **命名**：Notion 是抽象真实词，给多种内容形式留下空间。
- **Icon / Logo**：衬线 N、厚线条和略带透视的立方轮廓一起构成识别；不是单靠 N 字母。
- **字标 / 配色**：独立完整字标与黑白图形系统形成辨识，手绘式人物插画增加人的气息。
- **UI 延续**：页面、块结构与可组合内容延续组织能力；品牌无需把每个输入框画成立方体。本次官网已重点展示团队与 AI，不能把它描述为纯私人独立 App。[官方产品页](https://www.notion.com/)
- **为什么有效 / Collect 启发**：一致的轮廓、文字和插画可以建立强识别。Collect 应避免继承过强的工作空间、数据库和生产力语气。

图像校对：[App Store](https://apps.apple.com/us/app/notion-notes-tasks-ai/id1232780281)。

### 2.11 Arc / Arc Search：名称本身提供可扩展的形状语言

- **命名**：Arc 是短词，也能直接联想到弧线，名字与形状有内在联系。
- **Icon / Logo**：本次观测的是 Arc Search 的紫底、红蓝交叠 A 状弧形；不能把手机版本外观当作桌面 Arc 的所有版本。
- **字标 / 配色**：短名称便于与独立符号组合，鲜明色彩负责入口识别。
- **UI 延续**：Arc 官网展示 Spaces、Profiles、Themes 等个人空间组织方式；品牌形状与空间感有延续，但并非每个界面都重复大图标。[官方介绍](https://arc.net/)
- **为什么有效 / Collect 启发**：名称如果天然含有形状或关系，Icon 更容易与它一起发展。需要学习这种一致性，不借用交叠 A 和红蓝组合，也不为了品牌新增浏览器式空间功能。

图像校对：[Arc Search App Store](https://apps.apple.com/us/app/arc-search-find-it-faster/id6472513080)。

### 2.12 Cosmos：一个整体关系比很多独立细节更容易记住

- **命名**：Cosmos 把个人灵感组织联想到完整的小世界；语义广，也与大量其他产品共享词汇。
- **Icon / Logo**：白底上六个黑点围成环，负空间成为构图的一部分。
- **字标 / 配色**：完整字标与点阵符号分工，中性色给用户保存的视觉内容让位。
- **UI 延续**：集合、图像浏览及“个人灵感空间”的呈现支撑世界隐喻。官方展示色彩搜索的样例色值，不等于品牌主色。[产品官网](https://www.cosmos.so/)
- **为什么有效 / Collect 启发**：集合可以用整体结构表达，不必描绘文件夹。Collect 如果选择“小世界”，必须形成自己的组织关系，不能重用六点环、球形拼贴或星空套路。

图像校对：[App Store](https://apps.apple.com/us/app/cosmos-search-discover/id1577975475)。

### 2.13 Flighty：拟物可以简洁，复杂度来自结构而非材质一项

- **命名**：Flighty 保留飞行词根，语气比正式航空术语亲近。
- **Icon / Logo**：深色背景上的单架白色立体飞机。虽然有材质与光影，主轮廓仍然只有一个明确对象。
- **字标 / 配色**：短字标易阅读；黑白基底与少量紫色强调并存。
- **UI 延续**：航班信息、地图和状态层级建立可靠感。Apple 对其设计的评价特别强调清楚的信息呈现。[Apple 设计案例](https://developer.apple.com/news/?id=970ncww4)、[官网](https://flighty.com/)
- **为什么有效 / Collect 启发**：不能把“成熟图标”误解为一律纯平面。Collect 仍应先验证单色轮廓，材质是否加入留到下一阶段；无需复刻飞机或复杂立体渲染。

图像校对：[App Store](https://apps.apple.com/us/app/flighty-live-flight-tracker/id1358823008)。

### 2.14 Bears Gratitude：角色有效，因为它承担持续的产品关系

- **命名**：角色与使用目的结合，名字不追求抽象，理解成本低。
- **Icon / Logo**：暖粉背景、白色熊、红色心形与小配角，主要轮廓有清楚的情感动作。
- **字标 / 配色**：可读的完整名称配合柔和色彩；不靠精细装饰字建立识别。
- **UI 延续**：角色继续出现在日记、鼓励和插画中。它不是只存在于桌面的一张贴纸。[Apple 产品故事](https://apps.apple.com/sg/iphone/story/id1748200446)
- **为什么有效 / Collect 启发**：角色能建立陪伴，但需要长期内容与表达投入。Collect 的主体是用户自己的收藏，强角色容易抢走注意力，本轮不推荐发展吉祥物。

图像与产品介绍：[App Store](https://apps.apple.com/us/app/bears-gratitude/id6443609622)。

## 3. 成熟 App 的命名规律

以下是跨案例的设计推断，不是对某种命名方式成功率的统计结论。

| 规律 | 样本 | 对 Collect 的应用 |
| --- | --- | --- |
| 先选产品给人的感受，再选词 | Sofa、Day One、mymind | 从陈列、归属、经历出发，不从功能字段出发 |
| 一个短隐喻可以容纳多类功能 | Cosmos、Craft、Notion | 不把名字锁死为游戏柜、数码账本 |
| 名称与行为 / 形状有联系 | Pinterest、Arc | 名字要能指导符号和产品语气，不能随后随意配图 |
| 字母不是必选项 | Letterboxd、Are.na、Cosmos | 先提炼独特关系；不默认 C、更不叠加 C + 柜子 |
| 易读与独占不是同一件事 | Things、Sofa、Craft | 常用词能好记，但新产品须另做搜索和同类冲突筛查 |
| 小拼写变化也有成本 | Letterboxd、Are.na | 需验证口述、输入与搜索，不以“看起来像品牌”代替可用性 |

名称筛选标准：说一遍能大致复述；输入不需要解释生僻字；含义能用一句日常话说明；能覆盖未来物品类型；不会强烈暗示交易、消费控制或库存；在初步检索中不与同类产品直接重合。

Collect 适合作为当前项目工作名，但已有 [Collect by WeTransfer](https://apps.apple.com/us/app/collect-by-wetransfer/id765359021)及其 [Google Play 页面](https://play.google.com/store/apps/details?id=com.wetransfer.app.live)。因此新品牌不宜仅靠增加一个随意后缀来获得辨识。这里是搜索与产品混淆风险判断，不是商标结论。

## 4. 官方 App Icon 要求摘要

### 4.1 Apple：当前规范已经包含分层与多种外观

核对版本：App icons 页面变更记录最近列出 2026-06-08；同时读取当前 Icon Composer 文档。下表聚焦 Collect 的 iOS / iPadOS，不能把其他平台的尺寸直接套入。

| 项目 | 官方内容 |
| --- | --- |
| 源画布 / Mask | 1024 × 1024 px 方形分层画布，系统应用圆角方形 Mask；不要预先裁圆角 |
| 安全摆放 | 核心居中，使用 Apple 模板网格。该页没有给 iOS 一个通用的“安全区百分比”，不可借用 Android 数值 |
| 外观 | Default、dark、clear light / dark、tinted light / dark；核心特征保持一致 |
| 细节 | 少量简单形状，避免极细线；文字只在品牌确有必要时使用，优先图形而非照片或 UI 截图 |

来源：[Apple App icons HIG](https://developer.apple.com/design/human-interface-guidelines/app-icons)。

Icon Composer 的当前流程是分层导入图形、在工具中设置背景与系统材质、预览各外观。官方建议使用可缩放图形、文字转轮廓；不要把画布 Mask 以及待由工具控制的模糊、阴影等提前烘焙进导出层。分层和资产目录有不同兼容处理路径，不能一概宣称“所有图标层都必须是一张完全不透明 PNG”。[Icon Composer 官方文档](https://developer.apple.com/documentation/xcode/creating-your-app-icon-using-icon-composer)

**对本研究的含义**：先设计稳定符号，再研究平台材质；这不要求 Collect 的 Flutter UI 增加毛玻璃，也不表示本阶段要更换 Xcode 资源。

## 5. 从案例中提炼的 Icon 设计规律

以下为 Collect 的探索准则，不冒充平台硬性要求。官方也没有规定所有品牌只能用几种颜色、必须使用负空间或必须无字。

1. **一个核心母题**：陈列、承托或印记选其一。不要把柜子、爱心、手柄、时间、货币、C 同时塞入一枚图标。
2. **先看轮廓，再看配色**：Cosmos、Are.na、Notion 的单色结构是好参照；Letterboxd 的色彩关系是另一条路。Collect 应先在纯黑白下验证，再决定色彩是否提供额外识别。
3. **负空间也必须有尺寸**：需要在缩小后留下可读间隙；只在 1024 px 上看见的细缝不是有效识别。
4. **控制主次而非机械计数**：初始探索使用一个明亮主色与一个浅背景，有必要时才增加小面积暖色。这是复杂度管理建议，不是官方颜色上限。浅色需要清楚的色相和轮廓差异，不能把所有元素都稀释到看不清。
5. **名称无需挤进 Icon**：字标用于应用介绍、关于页和品牌展示；小图标优先独立符号。若最终采用字母，也必须具有来自概念的独特处理。
6. **材料不能补救概念**：Flighty、mymind 表明材质并非禁区，但本项目先用平面轮廓验证。渐变与玻璃效果不能成为唯一识别来源。
7. **UI 延续是规则，不是贴 Logo**：一个曲率、一种强调色、一种标注方式和一致语气，通常比每个按钮重画品牌图案更自然。

## 6. Collect 的品牌定位：给喜欢留位置，看见就开心

### 6.1 已明确的核心感受

用户本轮明确：**“为我的喜欢留位置，让我看到它们就很开心。”**

产品定义据此更新为：**A personal place for the things you love.**

这是工作性定位句，不是最终名称，也不是注册过的品牌标语。它强调三件事：

- **我的喜欢**：由用户自己决定什么值得留下，无须昂贵、稀有或具备投资价值。
- **留位置**：物件在自己的收藏里有一个清楚、舒服的位置，方便找到和看到。
- **看见就开心**：满足感来自用户喜欢的物件本身，品牌负责营造轻快的观看环境。

游戏、数码产品、周边、纪念品只是起点，名字与符号应能容纳未来其他实物。价格、统计与记录继续辅助收藏，不作为品牌的第一句话。

核心路径：放入喜欢的物件 → 它出现在自己的空间里 → 打开时轻松看见 → 感到满足。这个定位不要求增加每日打卡、消费控制、社交排名或新的业务能力。

### 6.2 三项确定的设计约束

| 项目 | 当前决定 | 后续如何判断 |
| --- | --- | --- |
| 命名 | 只考虑英文品牌名，不再提出中文名或拼音品牌 | 读写自然、语义能解释、搜索混淆可控；英语母语者反馈仍待验证 |
| 默认图标 | 清新明亮，不以墨蓝、深绿、棕色或黑色作大面积品牌底色 | 对比浅色画布与较鲜明的主体色，检查真实尺寸轮廓 |
| 情感重点 | 归属与看见收藏时的开心 | 名字、图形与语气一起表达“喜欢在这里有位置” |

“只用英文名”不表示产品正文或 App UI 要改为英文。本阶段没有修改 UI。竞品中的暗色案例仍保留为研究事实，不能把它们当作 Collect 的新配色提案。

品牌默认图标明亮；平台的 dark / tinted / monochrome 外观作为兼容测试处理，保持同一核心结构，不另建立一套暗色品牌风格。

### 6.3 性格与语气

| 感受 | 表达方式 | 容易走偏的地方 |
| --- | --- | --- |
| 私人 | 自己的东西与自己的喜好是主体 | 不把定位当作未经核实的加密技术承诺 |
| 明亮 | 清楚的浅背景、干净的颜色和开放构图 | 大片浅灰、低对比造成模糊 |
| 亲近 | 适度圆润，字标可读，语气日常 | 幼儿化角色、过量泡泡字或甜品包装感 |
| 开心 | 喜欢的收藏容易看到，品牌有轻快感 | 不用夸张笑脸或奖励机制代替收藏体验 |
| 珍藏 | 物件得到认真展示，不比较价格等级 | 不变成古董、投资、库存或购物服务 |

工作性文案可探索：“Room for what you love.”、“Your favorites, right here.”。它们只用于解释方向，不宣称独占。中文界面可延续“喜欢的东西，都在这里。”这一直接语气。

## 7. 五个 Brand Territory 的当前比较

五个概念共同接受“喜欢、有位置、看到就开心”的定位约束，区别在于先强调哪一种感受。**B 最贴合用户原话，是当前首推；A 与 E 仍值得并列探索。** 用户补充了情感重点，并未正式选定某个方向。C 的记录能力和 D 的自主选择作为共同原则，不挤进每枚图标。

### A. 被认真看见：值得深入的陈列表达

- **核心概念 / 用户感受**：喜欢的物件被清楚地展示，打开时容易欣赏。
- **适合之处**：直接承接收藏墙、封面和详情页，跨品类自然。
- **不适合之处**：独立强化时容易像公共美术馆或专业展览，弱化私人、轻快的感受。
- **英文命名语言**：看见、喜欢、展示的自然词语，不用画廊式庄重名称。
- **图形 / Icon**：一个圆润物形与短支撑的主次关系，避免实体柜体和四宫格。
- **颜色 / 字体倾向**：晴空蓝、浅蓝白、少量暖黄；开放、清楚的英文无衬线字标。
- **当前用途**：进入三条深入路线；英文候选 DearShelf / DearPerch 由“喜欢之物有一个可见位置”的关系发展。

### B. 为喜欢留位置：当前优先推荐

- **核心概念**：给喜欢的东西一个私人位置，并让它们容易被看见。
- **用户感受**：属于我、放在这里很舒服、打开就开心。
- **适合之处**：与用户本轮原话一致；昂贵设备和普通纪念物都能被纳入，延续当前圆润风格。
- **不适合之处**：若只强调容纳，容易变成收纳、仓储或家居产品；只强调开心，又会像情绪工具。
- **英文命名语言**：fond / dear 表达喜爱，room / shelf / porch 表达位置，joy 表达观看后的感受。只在语义成立时组合，不靠随机后缀制造品牌感。
- **图形语言**：开放的承托曲线、被留出的空间、一个被安放的物形；物形本身是主角。
- **Icon 可能性**：一条开放的圆润曲线承托一个简单物形。只看轮廓也要看出“它有自己的位置”，不默认字母、柜子或盒子。
- **颜色 / 字体倾向**：薄荷绿、晴空蓝、奶油黄与浅色背景；字腔开放、轻圆润、适度字重的英文字标。
- **当前用途**：进入三条深入路线，优先比较 Fondroom / Fondplace；推荐不等于已经替用户选定方向。

### C. 物件留下经历：作为记录支撑

- **核心概念 / 用户感受**：物件可以连着经历，但不必先有故事才值得收藏。
- **适合之处**：现有日期、描述与照片就能承载，不需要扩展业务。
- **不适合之处**：作为主定位容易变成日记或回忆相册，把开心变成怀旧或写作负担。
- **英文命名语言**：简短记录与保留经历的表达，本轮不以故事、档案或时间为名称中心。
- **图形 / Icon**：轻量标注、清楚留白；不把切口、时钟或书签额外叠到主图标上。
- **颜色 / 字体倾向**：浅杏色、奶油白与明亮蓝；现代无衬线，不用复古棕色或手写字体。
- **当前用途**：保留产品记录能力，视觉服务于明亮的私人收藏空间。

### D. 由自己定义的精选：作为共同原则

- **核心概念 / 用户感受**：喜欢由我决定，不需要别人评价。
- **适合之处**：对各种物品开放，保护用户的收藏动机。
- **不适合之处**：星形、认证勾和“精选”语言容易像推荐平台或购物品牌。
- **英文命名语言**：偏爱与自主选择，不使用等级、价值或购买词语。
- **图形 / Icon**：若采用个人印记，必须区别于通用星形；本轮不发展独立符号。
- **颜色 / 字体倾向**：浅珊瑚与浅背景，清楚的中等字重，避免促销式对比。
- **当前用途**：融入 B 的语气，不产生第四套视觉系统。

### E. 日常里的小世界：值得深入的明亮表达

- **核心概念 / 用户感受**：不同物件共同组成一个有个人性格的空间。
- **适合之处**：跨类别、长期积累、整体浏览都能支撑。
- **不适合之处**：容易接近 Cosmos 或社交社区，抽象宇宙也可能让语义变远。
- **英文命名语言**：自己的范围、局部空间，不用宏大的宇宙词汇。
- **图形 / Icon**：一个开敞的观看入口与简单物形，避免六点环、星空或四格结构；区别于 B 向上承托的曲线。
- **颜色 / 字体倾向**：奶油黄、晴空蓝与浅杏，开放、轻快的英文字标。
- **当前用途**：进入三条深入路线，探索 Joyporch / Dearporch；用轻快、亲近的小地方解释开心，避免宏大宇宙隐喻。
