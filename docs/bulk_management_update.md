# 批量管理与长按快捷删除

日期：2026-10-01。沿用现有 Dearshelf 展柜、圆角、配色和封面展示方式。

## 使用方式

- 点击展柜收藏数量右侧的「批量管理」，进入多选模式。卡片左上角显示选中标记，选中卡片显示绿色边框。
- 点选、取消点选，或使用右上角「全选 / 全不选」。全选作用于当前搜索或分类筛选后的列表，包括暂时未滚动到的藏品。
- 底部「修改分类」打开现有圆角分类面板；选择后统一修改选中藏品的分类。
- 底部「删除」先确认选中数量和藏品，再执行批量删除；取消确认保留当前选择。
- 点击左上角关闭或手机返回键退出多选，回到正常浏览。
- 正常浏览时长按卡片，弹出「批量管理 / 删除收藏」快捷面板。快捷删除无需进入详情，仍需确认；从快捷面板进入批量管理时自动选中长按的藏品。

## 行为与数据边界

- 本轮只增加批量改分类和批量删除。其他页面、统计规则、搜索、草稿、图标、备份格式和数据库结构保持现状；没有新依赖或迁移。
- `ItemRepository` 增加两个必要的批量方法，使用现有 `items` 表、当前用户过滤及明确的 ID 列表。改分类只写 `category` 和 `updated_at`，保留其他信息，包括游戏信息。
- 单次最多处理 100 件，大量选择按组顺序处理。删除只清理数据库实际返回的已删除记录对应封面，并限制存储清理并发数；封面清理失败沿用原有机制，不把数据库删除成功误报为失败。
- 执行时显示当前操作及处理进度，并禁止重复操作。成功后合并服务端确认的结果到当前会话数据，展柜和统计同步变化，不重新请求整个列表或重新生成所有封面链接。
- 网络失败或返回数量不足时，保留已确认完成的结果，刷新核对列表，并保留剩余选择供检查或重试。多个组之间不承诺整个操作一次性回滚。
- 多选状态绑定藏品 ID，不绑定排序位置；刷新后去掉已不存在的选择。批量写入后的缓存更新会阻止之前正在返回的旧列表覆盖新结果。
- 为验证完整首页流程，首页构造函数支持可选的数据依赖注入；正常 App 的初始化方式和调用方式不变。
