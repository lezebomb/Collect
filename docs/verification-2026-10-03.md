# 2026-10-03 验证记录

本轮包含分类重命名、加载缓存优化、PC 自动选择数字版，以及多个 JSON 藏品清单导入。沿用现有圆角、配色、图标及页面布局。

## 数据与权限

- 未新增或修改数据库表、字段、索引；现有备份格式保持不变。
- 唯一数据库迁移 `20261003081836_rename_collection_category.sql` 已部署到当前 Collect 项目：分类定义和当前用户的关联藏品在同一事务内改名。新名称冲突或操作失败会回滚；仅更新分类及更新时间，保留其他藏品字段。
- 函数使用 `SECURITY INVOKER`、空 `search_path` 和显式 `auth.uid()` 所有权条件，继续遵守现有 RLS。已查询确认匿名角色无执行权限，已登录角色有执行权限。
- 未增加依赖。批量导入复用现有 `items` 和 `user_categories` 接口，不新增数据库迁移；存档导入仍走原有流程。

## 加载优化

- 收藏列表按账号缓存，并合并同一轮进行中的请求；新增、修改、批量操作、改名和导入直接合并已确认的数据，不重新获取全部列表。
- 本地账号隔离的收藏快照先恢复展柜、统计和设置，随后后台同步。无缓存时，收藏先到即可显示，不等待偏好和分类。失败保留已有内容，显示重试提示；手动刷新仍查询最新数据。
- 防止旧加载结果覆盖刚完成的修改；缓存写入按顺序保存，退出登录清理云端数据缓存，保留草稿。
- 已缓存的封面直接读本地文件，避免为了显示已有图片再等待签名链接；没有缓存时使用原有签名链接期限及下载缓存。
- 统计复用已计算结果，只有藏品或筛选条件变化时重新计算。
